# S8 Structure veto

## Question

Does one tag-driven predicate (`fractalbuildings:excluded_from_cities`) keep foreign surface structures out of city cells at both start generation (`ChunkGenerator.tryGenerateStructure`) and `/locate` (`StructureCheck.canCreateStructure`)? Follow-up to [keeping-structures-out.md](../worldgen/keeping-structures-out.md), option C.

## Result

**Yes.** Two small `@Inject(HEAD, cancellable)` mixins sharing `CityVeto.vetoes(structureHolder, chunkPos)` work on 26.3. With a fixed city cell over a known village chunk:

- generation produces no village start in the cell, and still produces one in every village chunk outside it;
- `StructureCheck.checkStart` (the `/locate` primitive) reports exactly the baseline villages minus the cell;
- the two agree chunk for chunk (no `/locate` target without a start, no start that `/locate` hides);
- mineshaft starts inside the cell are identical with the veto on and off (tag-driven, so underground structures are untouched).

## Evidence

Server test `StructureVetoGameTest.villageVetoedAtGenerationAndLocate` (`mod/src/gametest/...`, registered in the gametest `fabric.mod.json`), fixed seed 8001, 29x29 regions of village candidates (all 5 village structures):

| Step | Veto | Result |
|---|---|---|
| `/locate` primitive over all candidates | off | 190 candidate village chunks |
| cell = chunk (-19,42) +-400 blocks, margin 0 | on | 189 (exactly baseline minus the 1 chunk in the cell) |
| `createStructures` on each of the 190 chunks | on | vetoed chunk: no start; 189 others: village start (0 missing) |
| control: `createStructures` on the vetoed chunk | off | village start (so the hook is the cause) |
| mineshaft starts, 33x33 chunks around the cell centre | on vs off | identical; 8 starts in the cell |

Runtime ~35 s (first generation ~20 s of JIT warm-up). **Mutation checks:** removing `ChunkGeneratorMixin` fails "no village start at vetoed (-19,42)"; removing `StructureCheckMixin` fails "locate disagrees with the cell". Each hook is tested independently.

## Exact hooks (26.3, Mojang names, unobfuscated; read with `javap`)

- `ChunkGenerator#tryGenerateStructure(StructureSet.StructureSelectionEntry, StructureManager, RegistryAccess, RandomState, StructureTemplateManager, long, ChunkAccess, ChunkPos, ResourceKey<Level>, Climate.Sampler) : boolean`, **private**. `@Inject(method="tryGenerateStructure", at=@At("HEAD"), cancellable=true)` with the full parameter list plus `CallbackInfoReturnable<Boolean>`; `cir.setReturnValue(false)` makes `createStructures` try the set's next weighted entry. Structure = `entry.structure()` (a `Holder<Structure>`), position = the `ChunkPos` argument.
- `StructureCheck#canCreateStructure(ChunkPos, Structure) : boolean`, **private**. `@Inject(HEAD, cancellable)`; the structure is a bare `Structure`, so the mixin `@Shadow @Final RegistryAccess registryAccess` and calls `lookupOrThrow(Registries.STRUCTURE).wrapAsHolder(structure).is(tag)`.
- `StructureCheck#checkStart(ChunkPos, Structure, StructurePlacement, boolean) : StructureCheckResult` is public. It returns `START_NOT_PRESENT` when `canCreateStructure` is false and **`CHUNK_LOAD_NEEDED`** (not `START_PRESENT`) when it is true and no stored chunk data exists. Test "possible" as `!= START_NOT_PRESENT`.
- Predicate: `structure.is(TagKey<Structure>) && cellExpandedByMargin.contains(chunk middle block)`. The tag is `data/fractalbuildings/tags/worldgen/structure/excluded_from_cities.json` (`#minecraft:village`, `minecraft:pillager_outpost` in the spike). No mixin refmap is needed (unobfuscated names). `fabric.mod.json` gets `"mixins": ["fractalbuildings.mixins.json"]`.

## Explorer maps and `/locate`

Per bytecode, `ChunkGenerator.findNearestMapStructure` → `getNearestGeneratedStructure(...)` → `StructureManager.checkStructurePresence` → `StructureCheck.checkStart`. So anything built on `findNearestMapStructure` (`/locate structure`, explorer map items, dolphin/eye-of-ender tag lookups) goes through the same hook. I called `checkStart` directly and did **not** run the `/locate` command or craft a map.

## What it means for the design

- Option C holds. Both hooks are cheap pure lookups (one tag test + one box test per candidate start, rare).
- Veto is a pure function of (structure, chunk position), so it stays deterministic and order-independent; the real region field slots in for `inCell` (margin from F2-F1 edge distance; **not tested here**, the cell was a fixed box with margin 0).
- The test harness is reusable: the game-test server's world is hard-coded flat (`WorldPresets.FLAT_ALL_DIMENSIONS`, no villages), so the test builds its own NORMAL overworld generator, `ChunkGeneratorStructureState`, `StructureCheck` (public ctor, no-op `ChunkScanAccess`) and `StructureManager`, then calls `createStructures` on throwaway `ProtoChunk`s. Use this pattern for any later worldgen-level test.

## Fragility and limits

- Both targets are **private** methods with long signatures; any parameter change in a future MC version makes `defaultRequire: 1` fail at startup (loud, good). Pin the signatures in this note and re-check with `javap -p` on each MC bump. Lithostitched / other mods that wrap `findValidGenerationPoint` are unaffected (we hook the call sites).
- Only the start *chunk* is known before generation: a village starting just outside the cell can still extend into it. Margin must cover the structure radius (jigsaw max 128 + 12; vanilla villages 80). Not measured here.
- `StructureCheck` memoises per (structure, chunk) (`featureChecks`) and prefers stored chunk data. Changing the cell on a live world would not un-spawn or un-hide existing villages; with cells derived from the seed they never change, so this is fine. The test builds a fresh `StructureCheck` after flipping the veto for that reason.
- A custom generator that overrides `createStructures` bypasses the generation hook.
- Structures that are not placed through `StructureSet` selection (e.g. `/place structure`, other mods' direct `Structure.generate`) are not vetoed.

## How to re-implement properly

Replace `CityVeto` fields with a lookup into the real region field (pure core, probes-style interface); margin from edge distance; keep the two mixins and the harness; add a margin test (village just outside the cell whose bounding box reaches in) and a `/locate` command smoke test through `Commands`.
