# S7 Terrain flattening by wrapping the router

## Question

Can we level a city area by wrapping router `final_density`, router `chunk_surface_level` and the aquifer `surface_level` (never `preliminary_surface_level`), with the planner reading unwrapped terrain?

## Answer (vanilla, seed 8, hill site at (-576,-192), 64x64 plateau, 24-block smoothstep fade)

**Yes, it works.** Wrapping is done by a mixin on the `NoiseGeneratorSettings.noiseRouter()` and `aquifers()` accessors (cached wrapped instance per original, only for settings with aquifers). `getBaseHeight`, `RandomState` and `NoiseChunk` all read through those accessors, so every consumer sees the wrapped terrain. No Lithostitched needed. Wrapper: `lerp(mask, final_density, yClampedGradient(L-32, L+32, 1, -1))`; `lerp(mask, chunk_surface_level, constant(L-12))`; same for aquifer `surface_level`. The mask is built only from `gradient` (X, Z axes), `min`, `square`, `mul`, `add` nodes.

| variant (L) | getBaseHeight within +-1 of L | placed ground within +-1 | bare-stone top columns | getBaseHeight equal to original | unwrapped read equal to original |
|---|---|---|---|---|---|
| base (none) | n/a | n/a | 0.5 % | 99 % (vs placed) | 100 % |
| cut, final_density only (85) | **100 %** | 98.5 % | **20.0 %** | 2 % | 100 % |
| cut, all three (85) | **100 %** | 98.5 % | **0.0 %** | 2 % | 100 % |
| fill, final_density only (109) | **100 %** | 97.9 % | 0.6 % | 2 % | 100 % |
| fill, all three (109) | **100 %** | 97.9 % | 0.6 % | 2 % | 100 % |

Final run (merged code, assertions on): BUILD SUCCESSFUL, 2 m 52 s.

- Cut levels: 13 blocks below the median, up to 27 below the highest column. `final_density` alone leaves **bare grey stone** on the cut floor (`cut-fd-closeup.jpg`); all three wrapped gives dirt/snow (`cut-all-closeup.jpg`). Fill is clean either way (`fill-all-closeup.jpg`), as the research predicted: prefer fill.
- Flooding was **not reproduced**: 0 fluid blocks above ground in any variant; 88 fluid blocks within 30 blocks below ground in both cut variants (not caused by the aquifer wrap: same with and without). Hill site was at y 80-112, far above aquifer fluid levels; a site near sea level is untested.
- The planner read works: `RandomState.getSampler(originalFinalDensity)` sampled with `SamplerContext.EMPTY_UNCACHED` and `DensityVolume(1, 384, 1, x, -64, z)` gives the original ground height in 100 % of sampled columns while the world is wrapped (the mixin keeps `wrapped -> original`).
- Cost (loadavg 13-17, lavapipe busy): final run 30-40 ms per chunk wrapped vs 45 base (vanilla), 72-123 vs 102 (Terralith+Tectonic): noise dominates, cost not measurable above it; `getBaseHeight` 275-390 us per column in all variants. Wrapping adds nothing visible.
- Caveats: inside the mask `final_density` is replaced, so caves, ore veins and the beardifier are gone in the plateau (full override, no depth band); a real version should blend only a band around the ground using the unwrapped height. Plateau is a square; shape is arbitrary (any 2D density).

## Terralith + Tectonic (S2 jars, `-Ps2ModSet=terratectonic`)

Site (576,480), y 168, rocky peak, cut level 160 and fill level 175. Final run: BUILD SUCCESSFUL (5 m 26 s). Wrapped `getBaseHeight` is within +-1 of the level in **100 %** of columns for all four variants (original equality 11 % cut, 4 % fill), and the unwrapped read equals the original in **100 %**. So the three-slot wrap works under Terralith + Tectonic (which override the overworld router) with the same accessor mixin.

Pitfall: the *placed* ground (`OCEAN_FLOOR_WG` heightmap after surface rules) matches `getBaseHeight` in only 47 % of columns even without the wrap at this altitude (powder snow and surface rules replace top blocks), so the first version of the test, which asserted on placed height, failed. Assert on `getBaseHeight`; compare placed height only on low, ordinary sites. Bare-stone fraction: cut-fd 6.8 %, cut-all 0.4 %, but the whole site is a bare rock peak, so the screenshots show nothing useful: **appearance under the mods is untested** (needs a grassy site). Terralith 2.6.5, Tectonic 3.0.31, Lithostitched 2.0.6 on 26.3.
