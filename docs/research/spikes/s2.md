# S2: terrain probe accuracy over 10 seeds and 4 mod sets

## Question

Does `getBaseHeight(OCEAN_FLOOR_WG)`, asked before any chunk exists, match the
real ground over varied seeds (mountains, rivers, coasts) under vanilla,
Terralith, Tectonic and Terralith + Tectonic? Is the coarse screen's bias
(about -15) stable enough for a fixed correction? Do surface rules ever add
blocks above `getBaseHeight`? What does a column cost in game?

## Answer

- **Exact probe: yes, use it.** Over 10 seeds, 7 windows each (8x8 chunks:
  highest peak, coast, river, deep ocean, 3 land), about 0.8 M land columns
  per set, predicted equals the real surface after fill + surface rules in
  **99.05 % (vanilla), 99.92 % (Terralith), 99.61 % (Tectonic), 99.60 %
  (both)**; p99 |error| is 0 to 4. Worst seed: 95.9 %. Against the filled
  chunk alone (before surface rules) it is **100.00 % in every set and seed**,
  so the density pipeline is predicted exactly, mod wrappers included.
- **Every residual is a surface rule making the top block non-solid.** Never
  an addition on land: **B > pred in 0 land columns** in all four sets. The
  misses are `powder_snow` replacing the top (B lower by 1 to 15; 7,583
  columns in vanilla), and `water` pockets. So `getBaseHeight` is an upper
  bound of solid ground on land (before carvers), not a lower bound.
- **Surface rules DO add blocks above the prediction over ocean.** Frozen
  oceans: iceberg `packed_ice` / `snow_block` (surface-rule icebergs) up to
  **+60 (vanilla), +75 (Terralith), +97 (Tectonic), +99 (both)** above the
  predicted floor, in 5,000 to 7,700 ocean columns per set (seed dependent:
  0 in 5 of 10 vanilla seeds). `OCEAN_FLOOR_WG` ignores them; they are
  solid above sea level. A site check that wants "no solid thing above the
  waterline" must look at the water surface too, not only the floor.
- **Carvers** (vanilla only; see Caveats): 1.2 to 3 % of land columns end
  lower than predicted, down to -52 (cave mouths, ravines). Previous in-game
  figure (-11 to +19 with trees) agrees in kind.
- **Coarse screen: bias is not stable enough for a fixed +15.** Pooled median
  of (coarse - real) is -14 / -12 / -13 / -13 (vanilla, T, Tc, T+Tc), per-seed
  medians -16..-10, but after the pooled correction only **64 to 72 %** of
  columns land within +-4 and p90 |error| is 6 to 12 on good seeds. Worse
  on mountains: window median -18 (vanilla), **-56 under Tectonic** (p10
  -102), and Terralith has columns 150+ blocks off (floating islands, dunes,
  arches: p10 -154 in the peak window, per-seed stdev up to 60). Use the
  screen only to cull, with a margin of at least 20 and never for a final
  placement height; use the exact probe for anything that is built on.
- **Cost, server thread, single thread, warmed up, loadavg 5 to 12 (noisy)**:
  per column 0.32 ms vanilla, 0.75 Terralith, 0.76 Tectonic, 0.93 both
  (0.37 ms vanilla in an earlier run at load 10). A 16-block grid over
  512x512 (1024 columns): 136 / 300 / 428 / 584 ms. Coarse screen
  (`chunkSurfaceLevel` sampled uncached): 0.03 / 0.06 / 1.96 / 2.49 ms per
  column, i.e. **under Tectonic the "coarse" sample is slower than half an
  exact column**, so it is no longer a cheap screen. Per km^2 (1 column per
  16x16 block cell, 3,906 cells): 1.3 / 2.9 / 3.0 / 3.6 s on the worldgen
  lane (cost scales with columns, so coarser grids are linear savings).

## Evidence

Test: `mod/src/gametest/java/dev/fractalbuildings/gametest/TerrainProbeGameTest.java`
(server game test, `:mod:runGameTest`; not merged). Raw per-set tables
(per seed, per window kind, ocean columns, causes, cost) are in
`docs/research/spikes/s2-results/s2-<set>.md`.

Method, per seed (`RandomState` made from the seed, over the generator and
router of the `NORMAL` world preset, so the mods' datapack overrides apply;
fingerprint line in each result file shows biomes 67 vs 162 and distinct
`finalDensity` hashes):

1. Coarse 49x49 scan (128-block step, +-3 km) with `getBaseHeight` and a
   river-tag biome lookup to find windows: highest peak, coast, river, deep
   ocean, 3 land. 8x8 chunks each, about 450 k columns per seed.
2. **Predict first**: `getBaseHeight(x, z, OCEAN_FLOOR_WG)` and the coarse
   value for every window column, before any chunk of that seed exists.
3. **Generate for real** on a throwaway `ProtoChunk` per chunk, no world:
   `createBiomes`, then (reflection into the private `createNoiseChunk`,
   `doFill`, `buildSurface`) fill = stage A and surface rules = stage B,
   with the `StructureManager` overridden to report no structure starts
   (open terrain, no beardifier). Stage C: the real `buildTerrain`
   (fill + surface + carvers) on a second chunk with a null `WorldGenRegion`.
4. Compare using the same predicate as the heightmap
   (`Heightmap.Types.OCEAN_FLOOR_WG.isOpaque()`), top opaque block + 1.
   Land = predicted height > 63. 8 worker threads for steps 2 and 3 (the
   shared `RandomState` and generator held up).

Control: predicting from the wrong seed (seed + 1) drops "equal to B" from
98 % to 5.4 %, so the comparison can fail.

## Caveats

- **Features (trees, snow layers, structures) are not in the generation**:
  `applyBiomeDecoration` needs a `WorldGenLevel`. The earlier in-game
  vanilla figure (98.2 %, +19 with features) stands for that part.
- **The carver stage ran only under vanilla.** Terralith and Tectonic hit an
  NPE on the null `WorldGenRegion` (a mod carver reads
  `carverBiomeRegion.registryAccess()`); there stage C is reported equal to
  B, so the `=C %` and `C<pred` columns in those result files are not carver
  data. Wanted: build a real `WorldGenRegion` or a real level.
- The "ocean" window picks deepest ocean by the coarse grid; in seeds where
  it hits land the land columns count as land. Window kinds are labels, not
  guarantees.
- Terralith's skylands: `getBaseHeight` scans from the top, so a floating
  island counts as ground in the column; the coarse screen is far below it.
  Plan against `getBaseHeight`, and treat "overhang below" as unknown.
- Tectonic 3.0.31 and Terralith 2.6.5 were loaded together with their
  load-order default; the Terratonic overlay was not checked as active (the
  `finalDensity` hash differs from both alone, so something combined).
- Timing numbers were taken under other agents' load (loadavg 5 to 12) and
  the heavy lock; a decision on cost needs a quiet re-measure.

## Setup for S7 (Terralith + Tectonic in a server test)

1. `scripts/fetch-test-mods.sh` downloads Lithostitched 2.0.6, Terralith
   2.6.5+26.3 and Tectonic 3.0.31 (Modrinth CDN) into
   `~/.cache/fractal-test-mods` (override with `FRACTAL_TEST_MODS`).
2. `mod/build.gradle` (appended block): `-Ps2ModSet=vanilla|terralith|tectonic|terratectonic`
   adds the jars as `gametestRuntimeOnly files(...)`. Fabric's dev launcher
   treats classpath jars with `fabric.mod.json` as mods, jar-in-jar
   (apollib) included. No Loom `modImplementation` needed in 26.x.
3. In the test, take the generator from
   `registryAccess().lookupOrThrow(WORLD_PRESET).getOrThrow(NORMAL).createWorldDimensions()`
   (not the flat test world), build `RandomState.create(NOISE registry, seed,
   settings)`. The mods' overrides are visible through that registry
   (Terralith: 162 biomes; Tectonic: vanilla biomes, other router).
4. `scripts/s2-run.sh [sets...]` runs each set under the heavy lock; env
   `S2_SEEDS`, `S2_WIN`, `S2_OUT` shrink or redirect. Whole run is about
   10 to 15 min for 4 sets.
5. Only `getBaseHeight`, `RandomState.sampleBlockValueUncached(router.chunkSurfaceLevel(), x, 0, z)`,
   and `NoiseBasedChunkGenerator`'s private `createNoiseChunk` / `doFill` /
   `buildSurface` (reflection) were needed. `buildTerrain(...)` takes a
   `WorldGenRegion` (null works for vanilla).

## What it means for the design

- `TerrainProbe` = `getBaseHeight(OCEAN_FLOOR_WG)` is exact on land to within
  a few blocks (99 %+) across vanilla and the terrain mods; keep +-a few
  blocks tolerance for powder snow, carvers and features.
- Add a **water-surface check** for frozen oceans (icebergs add up to +99
  over the floor).
- Do **not** plan a fixed +15 on the coarse screen; use it only to reject
  obviously bad cells with a generous margin (and not at all under Tectonic,
  where it costs as much as the exact probe).
- Budget about 0.3 to 0.9 ms per exact column on the worldgen lane
  (about 1.3 to 3.6 s per km^2 at 16-block spacing) plus fewer, coarser
  samples for big cities.

## How to re-implement properly

Replace reflection with an access-widener on the three private methods, or
generate through a real `ServerLevel` in a dedicated world (gives carvers
under mods and features). Pick windows from a recorded terrain dump so runs
are comparable across mod versions.
