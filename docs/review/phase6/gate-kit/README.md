# Phase 6 gate: playtest kit

The Phase 6 gate is you playing a fresh world on three seeds, about an hour each, on the release candidate (plan step C2,
[phase6.md](../../../plans/phase6.md); [release plan](../../release-plan.md)). This folder is the kit for it: one page per
seed (where the settlements are, the roads between them, a route, fly-through frames), the checklist below and the
[known issues](KNOWN-ISSUES.md).

**This copy was made on the run branch before the release candidate exists** (bugs 6.19-6.22 are still in flight). It shows
the shape; it will be regenerated on the release candidate with the command below, and the settlement lists can change
wherever a merge changes the region layer or the roads.

# Regenerate

```sh
scripts/playtest-kit.sh --fly            # lists, maps and pages in seconds; --fly adds the fly-through (heavy, 30-90 min)
scripts/playtest-kit.sh --seeds random,random,random --fly   # three fresh seeds instead
```

`--seeds A,B,C` picks the seeds (`random` draws a fresh one), `--radius N` the listing radius (default 4096 blocks),
`--fly-from DIR` reuses an earlier fly-through output instead of shooting again. Header of `scripts/playtest-kit.sh` for
the rest. The settlement lists come from an offline plan of the seed (terrain sampled on the region layer's 64-block lattice,
then `fractal-cli roads`), the same decisions the game makes; each page says what `/fb locate` should answer at spawn, so a
disagreement shows at once.

# Starting the game

- **Desktop launch** (GPU rendering): log in to GNOME on the host as `agent`, then ask an agent to start the client
  (`setsid -f ./scripts/run-desktop.sh > run/desktop-client.log 2>&1 < /dev/null`, CLAUDE.md "Display / running the
  game"). Or run the built jar in your own launcher with Fabric Loader and Fabric API.
- **The seed** goes in on the world-creation screen (More World Options, Seed); there is no command-line seed. World type
  Default, Generate Structures on, commands allowed. Each seed page has the recipe.
- **Notes while you play:** `/fbnote <comment>` takes a screenshot and saves where you stand and what the planner put
  there; an agent turns a folder of them into a review page. How-to: [PLAYTEST.md](../../../PLAYTEST.md). It is on by
  default in a development run; with the release jar add `-Dfractalbuildings.debugNotes=true` to the JVM arguments.

# Checklist (one hour per seed, your call how)

- [ ] Spawn: how far is the first settlement, did anything look broken on the way?
- [ ] `/fb locate village` (and `town`, `city`, `metropolis`): the answer matches the seed page?
- [ ] Walk into a village from outside: approach road, edge, main street, the centre.
- [ ] Enter buildings: doors reachable, stairs walkable to the top, rooms furnished, upstairs too.
- [ ] Sleep in a bed; open chests (loot); trade if villagers spawned (hamlets and villages only).
- [ ] Follow an intercity road from one settlement's exit to the next (the seed page lists them).
- [ ] Elytra or creative flight over a city or metropolis: lag, holes, chunks arriving late?
- [ ] `/locate structure #fractalbuildings:settlement`: it finds a district (not the centre).
- [ ] A night in a city: what spawns, and where.
- [ ] A long `/tp` into an unvisited city: the hold message, how long until you can move.
- [ ] Anything in the [known issues](KNOWN-ISSUES.md) that is worse than written there.

# What to write in REVIEW

Under the "Phase 6 gate" item in [REVIEW.md](../../../REVIEW.md) (or an FBNOTE gallery that an agent links there):
per seed, pass or fail with a sentence, the worst three things you saw (FBNOTE names or coordinates), and whether any of
them blocks the release. Tag the notes as in your 2026-10-28 playtest (`#backlog-p6` blocks the release, `#backlog`,
`#backlog-polish`, `#hype` for gallery shots).
