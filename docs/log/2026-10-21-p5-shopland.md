# SHOPLAND: shopfront landings

Branch `claude/p5-shopland`, 2026-10-21. John: shop fronts with big glass windows make no sense at the top of a flight of steps, needs a landing/balcony.

## What was built

- `InstancePassV1.steps`: for a door above the ground (ground below floor - 1) of a type with `TypeLimits.stoop` (shop), candidate landings are tried before the old single-cell start. The landing is the door's row and, when the lot has 2+ rows outward, the next row, out to the lot edges over building-free cells, trimmed `k` cells at one end (smallest `k` first, both ends). The flight search (breadth-first, existing pass 1/2 and merge rules) starts from all landing cells at depth 0, so the flight goes down from the landing's edge. Landing cells = foundation column + STAIR block at floor level, as the old first step. Second leaf of a double door reuses it. No landing fits (or none needed): old behaviour.
- `ShopMassing.market`: the hall is set back 1 or 2 rows (by lot depth) so the landing is 2 deep and the flight runs in the lot's front margin. Arcades and enclosed shops use the 1-row landing in front of the wall (the walkway for arcades).
- `TypeLimits` gets a 12th component `stoop` (the 11-arg constructor stays, false). Everything stays in the lot (cells come from the lot rectangle), nothing in the street strip, so JT air rights are untouched.
