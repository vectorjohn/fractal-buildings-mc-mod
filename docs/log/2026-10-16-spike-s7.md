# S7 terrain flattening spike

Question: can router `final_density`, `chunk_surface_level` and aquifer `surface_level` be wrapped to level a city area, with the planner reading unwrapped terrain? Answer: yes. Findings: `docs/research/spikes/s7.md`.

- Built `S7Wrap` (mask from gradient/min/square nodes, `lerp(mask, original, level)` for the three slots) and an accessor mixin on `NoiseGeneratorSettings.noiseRouter()` / `aquifers()` with identity-cached wrappers; the wrapped-to-original map gives the planner the unwrapped `final_density`, sampled via `RandomState.getSampler` + `DensityVolume`.
- Test `S7ClientGameTest` (client game test): one base world finds a hill site and records original heights; four worlds (cut/fill x final_density-only/all three) measure levelling, bare stone, fluids, original-read equality, per-chunk time, and take screenshots (side, top-down, deepest-column close-up).
- Results (vanilla seed 8): `getBaseHeight` 100 % within +-1 of the level; bare stone on the cut floor 20 % (fd only) vs 0 % (all three); unwrapped read 100 % original; no flooding seen (site y 80-112). Terralith + Tectonic: same 100 %/100 %, appearance untested (rocky site).
- Pitfall found: asserting on the placed heightmap fails at a rocky/snowy site (47 % equal to `getBaseHeight` without the wrap). Assert on `getBaseHeight`.
- First run showed stale screenshots for the added views because of a perl `@p` interpolation eating the `tp @p` command; fixed.
- Cost not measurable above noise (loadavg 13-17). Known limits: full override inside the mask removes caves, ores and the beardifier (needs a depth band); near-sea-level flooding untested.
- Spike code (mixin, build.gradle S2 snippet, fabric.mod.json mixin entry) is throwaway and not to be merged.
