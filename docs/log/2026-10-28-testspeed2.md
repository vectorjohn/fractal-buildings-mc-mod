# TESTSPEED2: share planned sites across planner-core test classes

Follow-up to [TESTSPEED](2026-10-28-testspeed.md). Same host, `:planner-core:test` (6 forks, `forkEvery = 0`: a fork is reused for many classes, so a JVM-wide memo helps only classes that land in the same fork; classes are dealt out dynamically).

Changes (tests only, plus `maxHeapSize` 1g to 2g in `planner-core/build.gradle`):
- `DistrictsTest.shared(i)` / `details(i)`: soft JVM-wide memo of the synthetic site and its planned districts; used by the read-only checks of DistrictsTest, AvenueDistrictsTest, OldTownDistrictsTest, SquareLotsTest. Fresh-source/any-order tests keep `planned(i)`.
- `GateWorld.all()` memoised (the 9 gz dumps were re-parsed by every test); `GateWorld.sharedPlanner()` one planner per window with caches that hold the window (~75 tiles, about 70 MB), used by GroundWalkTest, BuildingCellExtentTest, WorldPlannerInvariantTest. Parity, Order, Isolation, CachePressure, Footprint keep their own planners.
- `TownProgramTest.town(i)` memo (its determinism test now calls `plan(i)` twice to stay fresh), `WallWalkTest.ring(t)` and `ringsOn(..)` memo, `LotRailTest.matrix()` memo.
- Moved to heavy: `DistrictsTest.invariantsHoldOverTheOtherSyntheticSites` (sites 75..149; sites 0..74 stay in `invariantsHoldOverManySyntheticSites`, same code). Nothing else dropped; no sample sizes shrunk.

Numbers (load 12-21 from other agents both times): full `:planner-core:test` 535 s before, 541 s after: no wall-clock gain under that load. Per class (before, from the TESTSPEED run set; after, in the full run): GroundWalkTest 216 to 74 s, WorldPlannerOrderTest 187 to 108 s (reads the memoised dumps), BuildingCellExtentTest 143 to well under 60 s, DistrictsTest 141 to 109 s, WallWalkTest 94 to ~52-103 s (depends on fork neighbours). SquareLotsTest did not improve (168 to 278 in the loaded full run; alone 149 before, 171 after, load differed). Honest reading: the fork split limits sharing and the suite is CPU-bound with other agents loading the box, so this is a modest cut in CPU, not a step change. Remaining cost is real work: per-site planning (DistrictsTest invariants 77 s, SquareLots 150 s) and WorldPlannerOrderTest's fresh-planner determinism cases (45 s eight-thread test) which must stay fresh.

Mutants (each fails a test of the changed class, reverted): `Grading.FILL_BELOW` 12 to 6 -> BuildingCellExtentTest.everyGroundFloorColumn...; `SpecPolicyV1.railRoomOk` always true -> 3 LotRailTest tests; `Districts.MARGIN` 8 to 2 -> DistrictsTest.invariantsHoldOverManySyntheticSites; `WallRing` tower/curtain step check loosened -> WallWalkTest.theRingLevels...; Grading deck +2 -> GroundWalkTest.junctionStepsDoNotGetWorse. Not found: a mutant for the shared `Briefs.frontY` (+2) in DistrictsTest (it passes, so that test never checked the filled frontY; unchanged by me).
