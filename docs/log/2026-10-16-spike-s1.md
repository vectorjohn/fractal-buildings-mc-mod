# Spike S1 biome footprint under mods (2026-10-16)

Findings: [docs/research/spikes/s1.md](../research/spikes/s1.md). Short answer: priming holds for Lithostitched and Terralith; under TerraBlender with several regions it needs a same-region anchor (a single fixed prime left 2-14 of 16,384 cells order-dependent). Cost in game: ~0.6 s/km2 primed on one thread (vanilla), up to ~1.3 s with Terralith + TerraBlender beside busy workers.

- Test (throwaway, not merged): `BiomeOrderGameTest`, `RegionInfo`, `tb/TbSupport`; build change: `-Ps1mods` in `mod/build.gradle`, Modrinth maven repo, `gametestCompileOnly` TerraBlender.
- Verified: `:mod:runGameTest` per mod set (vanilla, Lithostitched, TerraBlender, Terralith+Lith, TerraBlender+Terralith+Lith) all pass; cost runs under the heavy lock, load 5-17. Mutation (unprimed) fails with 73 diffs.
- Surprises: Modrinth maven ambiguous version number gave the NeoForge TerraBlender jar; an uninitialised TerraBlender parameter list silently behaves like vanilla (needs `LevelUtils.initializeBiomes`); the first TerraBlender run was therefore a false pass.
- Timings are noisy (other agents running); ratios (primed = ~2x unprimed) are stable. Re-measure on a quiet machine before a number decides a gate.
