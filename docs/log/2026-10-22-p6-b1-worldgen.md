## Findings

- **Door halves could be different woods**: `Variant.pick` hashed each cell, so a two-high door got `birch` below and `oak` above. Found by the game-test readback; fixed in `PieceRaster.emit` (upper half hashes the lower half's y).
- **Flag-2 `setBlock` in a `ServerLevel` runs neighbour shape updates**, which made world blocks depend on write order (doors popped, stairs re-shaped). Pieces write with flags 2|16; the raster already chose every shape.
- `postProcess` has no `GenerationContext`; planners are keyed on `level.getChunkSource().randomState()`. A weak map cannot work (planner -> probes -> key), so the map is strong and cleared on `SERVER_STOPPED`.
- The flat game-test world is not a noise generator, so it has no planner; tests install one with `WorldPlanners.overrideForTests`.
- `waitForChunksRender` times out (60 s) on lavapipe for a 6-chunk view of a freshly generated tile; the client test catches that, logs, and screenshots anyway.

## Deviations (see ASSUMPTIONS)

Piece NBT holds the reference, slab y and generator version, not the brief (a reloaded piece rebuilds through the planner); the placement JSON has `salt` only (spacing is the tile grid); `overrideForTests` takes a planner instead of a function of the context; mod pieces are named `BuildingStructurePiece`/`GroundStructurePiece` to avoid clashing with the core records.
