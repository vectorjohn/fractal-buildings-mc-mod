# 3.10 Determinism and shell cache (S6)

Added `core/cache`: `IrSource` (extends `ShellSource`; `get`, `prefetch`), `DirectIrSource`, `CachedIrSource(capacity, executor[, builder])`. LRU by access order, one `CompletableFuture` per `SpecHash` key inserted under the lock and completed outside it; failed builds are removed; the cached spec is compared on hit so a 64-bit hash collision falls back to a direct build. No change to generator v0 sources (the `ShellSource` seam was enough). Only main edit: `// det-ok` on `IrValidator`'s membership-only `HashSet`.

Tests (`planner-core/src/test/.../determinism/`):
- `DeterminismTest`: 500 requests, sequential vs shuffled vs 4 and 8 threads; direct, cold, warm, capacity-2, prefetched-on-4-threads, evict-then-regenerate all byte-identical; one build per spec under 64 concurrent gets; failed build not cached; a flaky `IrSource` mutant is detected (with and without a cache in front).
- `GoldenDigestTest`: 64 cases, `golden/v0-digests.txt` (generated by this code, then re-verified in a fresh JVM).
- `DeterminismLintTest`: scan of main sources plus a pattern self-test (LinkedHashMap / StrictMath not matched).

Mutation checks: replacing the storeys draw with `System.nanoTime()` failed lint, order/threads, twice, cache and golden tests; with `new Object().hashCode()` it failed four of them (lint cannot see it, golden and in-process tests do). Reverted.
