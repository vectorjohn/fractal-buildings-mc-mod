# ORDERSIM S6: LakeVetoGameTest

`mod/src/gametest/java/dev/fractalbuildings/gametest/order/LakeVetoGameTest.java` (`// gametest-order: 7`, fast server game test).
It plans the flat-plains seed-6 town (as OrderGameTest), picks the building nearest the middle of the start boxes, fills the lake grid
with stone and places the registry's real `lake_lava` (`Registries.FEATURE`, `Feature.place(level, gen, random, origin)`):
- control: with `Mutations.LAKES` (veto off) the lake is placed and changes >100 cells (so the test can see a difference);
- veto: same origin, lake returns false, `LakeVeto.VETOED` +1, stone unchanged;
- free: an origin lifted until `claimsNear` is false is placed and not counted.

Verification: `:mod:runGameTest` passes (36 tests). Mutation: removing `LakeFeatureMixin` from `fractalbuildings.mixins.json`
fails only this test ("a lake over a building must not be placed", after the control passed). A renamed target would crash at startup
(`defaultRequire: 1`); not run separately.
The test does not use the planner of a real world (override planner, synthetic flat probes), so it checks the mixin wiring, not lake shapes.
