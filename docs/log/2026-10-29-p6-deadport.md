## Done
- **The link rule** (`WorldPlanner.linkState(EdgeKey)`): a settlement *serves* a link when one of its approaches reaches the link's port and keeps the water rule. Both ends serve it: `LIVE`. Neither: `DROPPED`. One end: `DROPPED` if the serving end has another link served at both ends, else `DEAD_END` (case c, waits for John's long-crossing answer; counted by `deadEndPorts`).
- **(a) another exit:** `approachRoads(site, owner)` (now cached, the list before the rule) adds, for each port no skeleton approach joins, an approach from another `EXIT` gate of the settlement: gates on the 32-block lattice in a tile the settlement plans, within 768 blocks of the port (or the radius), nearest first, at most 4; routed with the skeleton approaches' reroute (dry lattice nodes, grade limit, other approaches' gates kept clear) with the urban columns 30 steps dearer; drawn by the same code as every approach (`drawApproach`: street pins, port pin, water rule); refused when a column more than 16 blocks from its gate lies on a lot. Id `k<cx>_<cz>_<90 + port index>`.
- **(b) drop:** `roadColumnsAround` asks `RoadNet.query(cx, cz, filter)` without dropped links (a dropped road gives way to the next one on a shared column), and `approachesOf` draws `drawnApproaches` (no approach to a dropped link, at either end).
- `deadEndPorts` lists only roads still drawn with an unjoined port; new `droppedPorts`. Refactor: the approach attempt loop is `routeNodes` (behaviour unchanged for skeleton approaches), the per-approach drawing is `drawApproach`.
- **Order:** `linkState` reads approaches only, and approaches read skeletons, district plans and the graph, never a link state, so there is no cycle and nothing depends on which settlement or chunk is planned first. Skeletons and district plans are unchanged by this item: step-a approaches are decided after the plans and are not in `approachLines`.

## Round 2 (verifier: ApproachCacheTest all-caches-at-1 15 s to 1737 s)
- Cause: with every cache at 1, each road chunk recomputed the link state, so both ends' approaches and every district tile they cross were replanned per chunk; even memoised, the first plan of the far metropolis's approaches with all caches at 1 took tens of minutes.
- Fix: the link-state and served-link memos (`linkStates`, `servedLinks`: a few keys per entry) keep at least `LINK_MEMO_FLOOR` (4096) entries whatever `Caches` says, and when the planner's caches are below the defaults the served computation runs on a second planner of the same world with the default caches (`linkPlanner`; in the game, `Caches.forHeap` is never below the defaults, so it is the planner itself). Answers are pure, so which planner computes them changes nothing; the order argument stands and the cache-state mutant still fails `theRuleDoesNotDependOnWhatIsAskedFirst`.
- The separate per-settlement approach column cache is gone: `roadColumnsAround` reads the chunk's columns from `drawnApproaches` (the cached approaches), so approach columns are held once.
