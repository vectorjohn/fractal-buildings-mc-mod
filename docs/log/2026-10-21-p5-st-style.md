# P5 ST: biome style field (5.4)

Branch `claude/p5-st-style`. Core only; no wiring (DB does `Briefs.fill`).

## Done

- `core/style/StyleField(BiomeProbe, seed)`: `weights(x, z)` votes biomes on a 16-block lattice
  centred on the query point inside a 48-block disk (29 samples), returned as (style, weight)
  sorted by style id; `pick(lotX, lotZ)` is `Hash64.hash(seed, "lot-style", x, z)` weighted draw;
  `dominant(minX, minZ, sizeX, sizeZ)` is the mode over the world 16-lattice inside the rectangle
  (ties to the lower id). `styleOf(biome)` is public: null for water (ids ending `ocean`/`river`).
- `styles/biome-fallback.json` (`fb-biome-fallback/1`): biomes no style claims (savanna ->
  desert, dark forest/windswept/stony shore -> taiga, cherry grove/beach -> plains, swamps ->
  jungle, stony peaks -> snowy). A style's own `biomes` list wins over the file; anything else is
  `plain`. All-water neighbourhood gives `plain`. `medieval` lists no biomes, so it is never picked.
- Tests `StyleFieldTest` (6): split desert/plains shares (>95 % / <5 % / 30-70 %), pure picks in
  shuffled order and seed sensitivity, 29 samples, fallback and unclaimed biomes, water and
  medieval, `dominant`, every vanilla biome resolves to a real style.
  `StyleFieldPictureTest` writes `planner-core/build/style-field/borders.png` (straight desert|plains
  border, wobbly jungle|plains border with a snowy pocket): looked at, the border is a clean
  dithered blend about 100 blocks wide, no stripes.
- Mutation: replacing the hashed draw with "always first" fails `splitBorderBlends` and
  `picksArePureFunctions`.
