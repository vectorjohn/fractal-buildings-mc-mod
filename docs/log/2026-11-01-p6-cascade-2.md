## Done

- `ExitTrim.cutBeyondWalk(src, road, m, plans)`: walks the same scan as `cut` outward from the hub over the columns' frontage only, and returns true ("the cut lies at or beyond column m, or there is none") at the first frontage column at or past m, provided no stop event (bridge start after frontage, lot-free run over `GAP`) happened on the way. A stop event, no frontage at or past m, or any doubt returns false, and `trimmedPlan` falls back to the memoised `fullCut` exactly as before. The proof is in the javadoc: no stop before j gives stop >= j and lastAll >= j, so keep >= j >= m. Veto rules (junction / quarter beyond) only matter when a stop event happens, which is the fall-back case, so the walk never evaluates them.
- Deviation from the plan: no `cutWithin` returning an exact `Cut` and no look-ahead constant. The exact cut needs `dropped` (lots beside the removed stretch, whole road), so it can't be bounded; the walk is a pure proof of the beyond case and the exact cut stays with `fullCut`. The walk is at most `GAP`+1 columns past m, a tighter bound than the plan's.
- `WorldPlanner.trimmedPlan`: `walkBeyond` memo per (settlement, road, m) before `fullCuts`. `-Dfb.exitcut.reference=true` restores the old path.
- Tests (`ExitCutWalkTest`): `aBoundedWalkAgreesWithTheFullCut` (every exit road, every m 0..n+1, all QuaySites + all gate windows; walk true implies full cut beyond; also asserts the walk proves at least a quarter of the provable cases), `trimmedPlansUnchanged` (every owned tile's `DistrictJson` equals a replay of the old trimmedPlan from the public ExitTrim API); metropolis variants `@Tag("heavy")`.
- Mutation: ignoring the stop events (`if (bridge || gap) return false` removed) fails both tests.
