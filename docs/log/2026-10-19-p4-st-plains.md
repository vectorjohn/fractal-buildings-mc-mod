# 4.7 St-plains

- `styles/plains.json` (extends `plain`, sets every sub-object): gable 4 / hip 2, overhang 1, dormers 25; plans box/L weighted, few T/U; no jetties; symmetric 2-3 bays, plinth, sills, shutters, door surround, `post` corners, no timber; birch/oak plank and plaster walls, cobble/stone foundation, brick/terracotta roofs (3-4 blocks per role). Biomes: plains, sunflower_plains, meadow, forest, flower_forest, birch_forest.
- `medieval.json` biomes now `[]` (moved to plains); `medieval` is requested by name, `auto` gives plains. Goldens (plain, medieval) untouched: `GOLDEN_STYLES` is fixed and no golden file changed.
- Block/biome id validity: `planner-core/src/test/resources/vanilla-26.3-blocks.txt` and `-biomes.txt`, generated from `Blocks.class` / `Biomes.class` fields of the 26.3 jar (javap, lower-cased), with the 16-colour `ColorCollection`s (26.x no longer has plain `WHITE_WOOL` fields) expanded by hand. Other style steps can reuse them (`PlainsStyleTest.lines`).
- `PlainsStyleTest`: all style palettes/biomes are real ids; plains gradient sizes, owns the plains family, medieval has none, no biome in two styles; 1000x2 house massings have 0 jetties, wings occur; 150 full plains houses pass every invariant and roofs are >= 90 % pitched gable/hip. Mutation: a typo block id (`andesyte`) fails the first test.
- `StyleLibraryTest` now expects `plains` for `minecraft:plains`. `cli MainTest.checkSeeds0to49...` pinned "6400" cases, which grows with each style: now matches any count with `failing: 0` (every later style step would otherwise break it).
- Gallery `house-plains` / `house-plains-flat` (seeds 0..15, 0 violations) vs medieval: plains is lighter (birch/oak plaster, grey cobble base, brick roof), no jetties or half-timber, symmetric facades with shutters and posts; roofs gabled/hip, some dormers. A first draft's grey stone-brick roof mix looked patchy and was reduced to brick/terracotta tones.
