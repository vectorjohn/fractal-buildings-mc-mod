# 2026-10-23 p6-palette

John's playtest: walls in styles with very different block colours read noisy and checkerboardy; timbers are fine.

**Cause.** `Variant.pick` (and the viewer's `styleColour`) choose `palette[role][cellHash(x,y,z) % n]` per voxel, so every wall voxel is an independent draw. With dissimilar entries (white terracotta / smooth sandstone / mushroom stem; snowy stone bricks / spruce / smooth stone / white terracotta; desert yellow terracotta) that is white noise. Also, the viewer `colours` lists had drifted from the real blocks (medieval walls drew cream while the game used pinkish white terracotta), so the gallery hid the problem.

**Change (palettes only, selection unchanged).** Per style, the bulk roles (wall, foundation, floor, roof) now hold near-identical colours; weights are by repeating an entry (the hash is uniform, so `[a,a,a,b]` is 75/25), so a contrasting block is a rare accent:
- medieval: wall white_terracotta x3 + mushroom_stem; roof bricks x3 + mud_bricks (was + granite); foundation cobblestone x3, mossy, stone.
- plains: floor birch x2 + oak (bamboo floor edges showed as yellow bands in game; this last edit is not re-shot in game); wall birch x3 + stripped birch wood (bamboo and smooth_sandstone gone; in game bamboo planks showed as yellow patches on birch); foundation cobble x2, stone, andesite.
- desert: wall sandstone/smooth/cut (yellow terracotta gone); roof sandstone family (terracotta gone); trim chiseled sandstone, cut sandstone (orange terracotta gone: it read as red dots); floor sandstone family (acacia gone).
- jungle: wall bamboo planks x2, stripped bamboo block x2 (birch and jungle planks gone); roof jungle planks x4 + one moss_block accent; trim/beam mostly one log kind.
- snowy: wall stone_bricks x4 + cracked_stone_bricks (spruce, smooth stone, white terracotta gone); roof spruce x4 + dark oak (stone bricks, snow block gone).
- taiga: wall spruce x3 + stripped spruce wood (dark oak gone); roof dark oak x3 + brown terracotta (mud bricks, deepslate gone).
- Timber framing (beam/trim of medieval/plains/taiga/snowy) untouched.
- `planner-core/src/test/resources/block-colours.json`: texture-average colour per block; the viewer `colours` of every style were regenerated from it (so viewer and game now agree). `PaletteCalmTest` asserts colours parallel to palette and equal to the table, and a max pairwise colour distance (walls 45, others 85 RGB units, which allows one accent).
- Existing tests adjusted: `VariantTest` (medieval wall set), `SnowyStyleTest` (spruce timber, not spruce walls), `BlockMapperTest` (snow_block no longer a roof id).

**Not done: patch/course selection** (brief item 3). With near-identical colours the per-cell draw reads as texture, and changing the hash input would change the `cellhash.csv` fixture, `Variant`, the viewer and every ledger digest for a look change nobody asked for after colours calmed. Candidate if John still wants intent: wall variant per face and storey band (hash of face id and storey), keeping `cellHash` for roofs.

**Goldens/digests.** The planner IR is roles, not blocks, so no IR golden changed (planner-core tests pass). Only the block ids a role resolves to changed, so mod ledger/world digests that hash block ids differ from before (none are committed goldens).

**Evidence.** `docs/review/phase6/palette/{house-*,shop-*}-{before,after}.png` (front-left, seeds 0-15; "before" is the old palettes drawn with true block colours). Before: snowy and jungle walls were confetti, desert had orange/yellow dots. After: each facade reads as one material with subtle shading.
