# FBNOTE: in-game playtest note command (2026-10-28)

John play-tests with screenshots and typed captions, then OCRs them (`scripts/ocr-screenshots.py`) and builds the REVIEW page by hand.
`/fbnote <comment>` records the comment and the debug data in game; a script builds the page.

**Done**
- Core (pure): `core/world/PlanLookup.at(planner, x, y, z)` gives an ordered map: settlement id and tier, tile, district, lot, building
  (id, type, style, seed, storeys), room (the IR room whose world boxes hold the feet), street (nearest centre line within half its width + 1),
  plaza; `{"settlement": null}` outside a settlement. `core/world/PlaytestNote`: the `fb-playtest-note/1` JSON writer and the switch
  `enabled(development, property, config)`. New `WorldPlanner.tileAt(x, z)` (default `grid().tileAt`) so the fixture planner, whose tile
  numbers are its own, can be looked up too.
- Mod: client entrypoint `client/FbNoteClient` (new `"client"` entry in `fabric.mod.json`; nothing else references the client package, so a
  dedicated server never loads it). Registers `/fbnote <greedy text>` through `ClientCommandRegistrationCallback` only when enabled
  (`-Dfractalbuildings.debugNotes`, a development run, or `debugNotes=true` in `config/fractalbuildings-client.properties`). The command
  queues the note; 3 client ticks later (chat screen gone) it fills the client fields, calls `Screenshot.grab(gameDir, "<ts>.png",
  gameRenderer.mainRenderTarget(), 1, ...)` and, with an integrated server, hands the planner read to the server thread, which writes the
  JSON. On a remote server it writes at once with `planner: {available: false, note}`. Git commit only in a development run (`git rev-parse`
  next to the game dir, 2 s limit).
- `scripts/playtest-gallery.mjs` (Node + ImageMagick): screenshots folder plus sidecars to `docs/review/playtest-<date>/REVIEW.md` in the
  playtest-comments layout (frontmatter, `![[x.jpg|800]]`, caption, one facts line) and 1280-wide JPEGs. Shots without a sidecar are listed as
  "(no note)" unless `--notes-only`. How-to: `docs/PLAYTEST.md`; command line in CLAUDE.md.

**Verified**
- `PlaytestNoteTest` (3: JSON escaping and key order, the switch, lookup in 40+ rooms of the sample town plus a street column and a point
  outside), `FbNoteCommandTest` (2: command absent when off, present and takes the whole line when on), `scripts/playtest-gallery.test.mjs`
  (15 checks, wired into `test-all.sh` as step `playtest-gallery`). Mutations: room lookup removed, development switch removed, `if (!on)
  return` removed: each fails its test.
- Client test `FbNoteClientGameTest` (seed 987654321, stands in a room of the nearest village, runs `fbnote test, with "quotes" and 123`
  through `sendCommand`): see the report for the run and evidence.

**Decisions** (also ASSUMPTIONS): the config flag lives in its own `config/fractalbuildings-client.properties`, not `fractalbuildings.json`
(that file is per-world defaults parsed by the core); an explicit `-D...=false` beats the development default so the "absent" case can be
reproduced in a dev run. The planner read takes the player's block position (feet), so the room matches the storey the player stands in.
