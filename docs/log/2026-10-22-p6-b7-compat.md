## What exists now

- `WorldPlanner.footprintNear(x, z, margin)` (core): is the block within `margin` of any settlement's disc (radius around its centre)? Region view only. `FixtureWorldPlanner` answers for its one site. Unit test `WorldPlannerFootprintTest` (rim, margin edge to the block, every direction, far away).
- `mod/.../compat/CityVeto` + two mixins (`ChunkGeneratorMixin` on `tryGenerateStructure`, `StructureCheckMixin` on `canCreateStructure`, S8's hooks, entries in `fractalbuildings.mixins.json`): a structure in `#fractalbuildings:excluded_from_cities` (village tag, pillager outpost, desert/jungle pyramid, igloo, swamp hut, mansion) cannot start within 160 blocks of a settlement footprint, at generation and at `/locate`. Off when the world's pinned `vetoVanillaVillages` is false (`WorldPlanners.setVeto`, set with the pinned config); off for generators without a planner.
- `BiomeAliasRules` (pure) / `BiomeAliases` (live), used by `LiveBiomeProbe`: `#fractalbuildings:no_settlements` biomes read as `minecraft:ocean` (multiplier 0); foreign biomes map by `c:is_*` tag, else plains. With this the coordinator can tick 6.2.
- `TerraBlenderPriming` (reflection only): with more than one TerraBlender region, `LiveBiomeProbe` primes an anchor inside the column's region (S1). Anchors: 16 candidates per region on a fixed lattice, first whose answer is independent of the other candidates' priming.
- Matrix: `-PmodSet=vanilla|lithostitched|terralith|tectonic|terratectonic|terrablender` in `mod/build.gradle` (jars in `~/.cache/fractal-test-mods` via `scripts/fetch-test-mods.sh`, run by Gradle when missing; S2's jars plus the TerraBlender 26.3.0.0.9 Fabric jar; run as black boxes, never read), `scripts/compat-matrix.sh`, test entrypoint `compat/tb/TbRegions` (two extra regions, S1's), client test `CompatClientGameTest`.

## Findings and limits

- **Cold cost of the veto:** `footprintNear` scans `(maxRadius + 160) / cellSize + 2` cells each way (169 cells at defaults) and each cold cell is a region decision (~20 ms). 190 candidates took ~20 s cold in the test (40 s for Terralith's 274); later candidates reuse cached cells and B4's warmer fills the same ones. A first village near a fresh area can stall one worldgen thread for a second or two. Cheap fix if B8 shows it: scan by tier bound, or let the warmer pre-resolve cells.
- Only a village's start chunk is vetoed; the 160 margin covers its reach. A village just outside can still touch the margin, never the footprint.
- In the client test the "inside" check is weak (0 of 10 inside have a start, but we do not know how many would have without the veto); the server test is the proof (A/B against a baseline).
- `LiveBiomeProbe` builds a TerraBlender anchor scan per probe (two per world); ~6400 region lookups, not measured separately.
- Gotcha: plain unit tests bootstrap registries without bound tags; `BiomeAliases` treats that as "no tag" (LiveProbeTest hit it).
