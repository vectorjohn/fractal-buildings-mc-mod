# 4.7 St-desert: desert style

- `styles/desert.json` (extends `plain`): biomes desert, badlands, eroded_badlands, wooded_badlands (disjoint from medieval/plain); massing plans box 2, L 1, T 1, U 3, courtyard 3; roof forms `{flat: 1}` with a 1-block wall parapet, no dormers/overhang; facade bays 3..4, 1-wide 1-high windows, blank corners, plinth, sills, lintels, cornice; palette of 3-5 block gradients (sandstone family, yellow/orange/plain terracotta trim, acacia beams/doors) with parallel viewer colours. No pass code changed, so golden files are unchanged (GoldenDigestV1Test passes untouched).
- Block ids checked against the 26.3 merged jar (blockstate assets, `Blocks` constants); `DesertStyleTest` keeps a whitelist, and the shared `vanilla-26.3-blocks.txt` from St-plains (not yet merged when I finished) also contains every id.
- `DesertStyleTest`: palette ids vanilla and <= 5 per role; the four biomes resolve to desert and no other style claims them; U+courtyard weight exceeds box; 48 house seeds on a 20x20 desert lot: invariants clean and 100 % flat roofs (>= 80 % required). Mutation: forms flat -> gable made it fail.
- Gallery presets `house-desert` (20x20 noise terrain, cutaway) and `tower-desert` (the block type was not merged; tower is the large type here). `npm run gallery` with FB_PRESETS=house-desert,tower-desert: 0 violations in all 32 cells. Looked at front-left: flat parapeted sandstone boxes, courtyard/U masses visible, small windows, orange terracotta trim bands; towers are flat-topped sandstone shafts. The viewer picks a colour per voxel, so walls look speckled (yellow terracotta in the wall gradient adds gold flecks); drop it from the wall list if that reads busy.
