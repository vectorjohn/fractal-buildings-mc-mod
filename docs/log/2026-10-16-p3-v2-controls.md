# 3.6 Viewer controls (V2)

Added a control panel to the viewer: seed box, slider and prev/next (plus left/right keys), style select, colour mode, layer checkboxes (terrain, foundation, shell, interior, roof, violations) and a "storeys up to N" slider. All state lives in the URL query.

- `state.ts`: pure URL <-> `ViewState`, `stepSeed`, `resolveSeed`, `toggleLayer`, `storeyVisible`. `source.ts`: `resolveSource` (`?ir=`, `?fixture=`, `gen/<style>/index.json` + `seed-N.json`, else bundled fixtures as a seed list), fake-fetch testable; S5's batch and V4's gallery plug in by writing `viewer/public/gen/<style>/`. `visibility.ts`: layer `visible` flags and the storey limit (collapses instance matrices; no mesh rebuild). `ui.ts`: DOM panel built once. `main.ts`: owns state, rebuilds only on seed/style/colour change; V3 mounts at the marked comment in `buildContent` and owns the `violations` group.
- Tests: Vitest `state.test.ts`, `source.test.ts`, `visibility.test.ts` (32 total); Playwright `e2e/controls.spec.ts` (layers via URL and checkboxes with no rebuild, storeys, batch navigation by keys/slider/box/style via a routed fake `gen/`, URL restore). Mutation: dropping the `storey >= 0` clause failed the storeyVisible test.
- Screenshots in `viewer/out/controls-*.png` looked at: shell+foundation shows walls, no roof; all layers shows terrain, roof; storey 0 hides the roof; medieval/palette shows brown trim and red roof.

Decisions: default seed list for bundled fixtures is an index into the fb-scene fixtures (only one today, so no scrubbing). `sample-house.json` is single-storey with roof boxes tagged storey -1, so the e2e storey test serves a copy with the roof at storey 1. If S3 tags roofs -1 the storey slider would hide them early; revisit then.
