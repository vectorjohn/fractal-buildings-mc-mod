# QUAYLAZY step 3a: QuayTrace over a bank interface

Branch `claude/p6-quaylazy-3a`. Plan: `docs/plans/quaylazy.md` step 3a. Not wired into `Districts` yet (step 3b).

## Done
- `QuayTrace` (planner-core `settlement`): `near(bank, minX, minZ, maxX, maxZ, m)` and `all(bank)`, over `Bank {near, ok, grade, prefetch}`. Node memo, `pointIndex`, chains with their runs, `partners`, cluster futures: all concurrent maps, never iterated for output; results are sorted by `order` key `{smallest column key, first column key, run size, part index}` (`QuayTrace.orderKey`).
- `QuayWhole(cols, y, steep, order)`: new top-level record (own file). `Districts.Build` keeps its nested 3-field record until 3b; **step 2 should use this top-level record rather than define another** (same name, same package).
- Cluster rule: chains join when run columns come within `MEET_REACH = 4` (Chebyshev); the scan looks `CLUSTER_REACH = 8` blocks round each run column (static check `CLUSTER_REACH >= MEET_REACH + STEP/2`). A cluster is graded once through `bank.grade`.
- `near()` filter: some column within `m` (Chebyshev) of the tile window; the caller passes `m + WIDTH/2` if it wants the footprint filter of the plan.
- `breakRing` and `runsOf` are copied into `QuayTrace` as statics (Build's is an instance method until step 2 makes it static; 3b can delegate).
- Stand-in chain source `WholeWindow` (contours the whole window once, indexed by cell) behind the `ChainSource {seeds, chainThrough}` seam; step 1's `Quays.seeds`/`chainThrough` replace it via `withSource`. Until then `near()` still reads the whole window (stand-in only).
- `Area.wf` is carried but unused by the trace; the bank's `near`/`ok` own it. Row prefetch for `all()`'s contour stays in the bank's `near` (3b), chain-read prefetch goes through `bank.prefetch`.
