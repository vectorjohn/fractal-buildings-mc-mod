# C15: `/fb places` dump for the index

- `planner-core` `world/PlacesIndex.build(WorldPlanner, x, z, radius)` (format `fb-places/1`): settlements whose disc meets the square (id, tier, centre, radius, bbox, `links` = intercity neighbours, `gates` = exit gates), their planned district tiles touching the square (id, tile, bbox, `lotsByType`, `notable` = built lots whose type is not house/cottage/hut: id, type, style, bbox, front facing). Pure planner data, no world blocks; every list sorted, fixed key order, written with `PlaytestNote.json`. `WorldPlanner.cellAt` added (package-private).
- Mod: `/fb places [radius [x z]]` (op level gamemasters; radius 16..4096, default 256; position of the source unless x z given) writes `<world>/fractalbuildings/places.json` and prints a one-line summary. `FbCommand.writePlaces` is the testable part.
- `scripts/worlds.sh generate` sends `fb places <r> <x> <z>` over the console before `save-all`, so each cached save carries `world/fractalbuildings/places.json` (waits for the log line, warns if absent). Not exercised end-to-end here (needs a full pregeneration); the command and file are tested by the game test, the script edit is `bash -n` clean and the self-test uses a stub generator.
- Tests: `PlacesIndexTest` (planner-core: deterministic, sorted, lists the hamlet and its districts), `PlacesGameTest` (server: the file into the world folder twice identical and names the hamlet; command registered; no file on the flat gametest world). The gametest world is flat, so the hamlet comes from a synthetic-plain planner (seed 1), not the world.
- Deviation: no per-building door block. A door position needs the building plan (`buildings(ix, iz)`, whole tile generation per district); the index gives the front facing instead.
