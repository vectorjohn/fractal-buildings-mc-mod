# ORDERSIM S1: SimBoot, SimWorld, SimLevel

Branch `claude/p6-ordersim-s1`. Test-side only (`mod/src/test/java/dev/fractalbuildings/mod/ordersim/`), no production change.

- `SimBoot`: Bootstrap once, block and fluid tags bound via `prepareTagReload`, `VanillaRegistries.createWorldLookup()`, a hand-built `PalettedContainerFactory` (all biomes in the `IdMapper`), `biome(id)`, `feature(key)`.
- `SimWorld`: window of real `ProtoChunk`s filled from a `TerrainProbe`/`BiomeProbe` (grass at floorY-1, water to surfaceY-1), heightmaps primed then status FEATURES (WORLD_SURFACE_WG frozen), write log with writer labels (+ optional StackWalker frame), last-writer per cell, zone violations, `promote(cx, cz)`.
- `SimLevel`: `WorldGenLevel` `Proxy` bound to a chunk, read/write zone radius 1 by default (write outside: dropped and logged, `ours` when the label starts `ours:`; `getChunk`/`getBlockState` outside the read zone throw), method table per the plan, defaults via `invokeDefault`, anything else throws `UnsupportedOperationException` naming the method.
- `SimWorldTest` (9 tests, about 9 s with the 3 s boot): tags bound, terrain vs probe, real dark_oak (2x2 trunk, dirt under it), lake_lava (lava + cave air), freeze_top_layer (snow in snowy_plains, none in plains), zone enforcement, promotion, FoliageClear on a floating blob, unmodelled method.

Deviations from the plan:
- `getSeaLevel/0` is modelled (63); `Biome.shouldFreeze` needs it.
- Post-processing: `BlockState.getPostProcessPos` returns null for almost every block. In 26.3 only brown/red mushroom, soul sand and magma block ask for it, so the plan's "oak fence reshaped at promotion" test is a floating brown mushroom (marked: pops off at promotion; written with flag 16: stays). A null position is not marked.
- The write `flags` argument is logged as given; `ChunkAccess.setBlockState` returning null (no change) is not logged.

Mutation check: making `inWrite` always true fails `zoneIsEnforced`.
