# BEDFIX: bed halves lost at chunk borders

**Cause (traced with a temporary mixin on Proto/LevelChunk.setBlockState, forward-order B2 run):** 5 bed halves were replaced by air with flags 2 from `TreeFeature.place` -> `StructureTemplate.updateShapeAtEdge` -> `WorldGenRegion.setBlock`. After a tree is placed, vanilla runs `updateShape` on the cells around it; `AbstractBedBlock.updateShape` turns a half into air when its partner is not a bed. With B5 r2 each chunk wrote only its own half, so the lone half (partner in a chunk not generated yet) died if a tree grew next to it. Includes the reported 1165,70,-9441. Not reproducible in ServerLevel tests (no tree pass).

**Fix:** `HookPlacer.bed` writes both halves from whichever chunk reaches the bed, the foreign half only when `WorldGenRegion.ensureCanWrite` allows it (non-region levels keep the old own-chunk-only rule). Both halves come from the same raster-derived state, so the second chunk writes identical blocks: deterministic, order-independent; the ledger override is idempotent.

**Verification:** `DistrictOrderClientGameTest` (forward order) with `BED_LOSS_LIMIT = 0`: before the fix 5 BEDTRACE removals; result after: see the report. Mutation: the old code is the failing case.
