# QUAYFAST step 1: the run walker in `Quays`

Plan: [quayfast.md](../plans/quayfast.md) step 1. Branch `claude/p6-quayfast-1`.

- `Quays.segmentsIn` (every segment of a cell box, scan order); `seeds` now uses it (output unchanged).
- `Quays.runThrough(near, ok, i0, j0, i1, j1, a, b, t)` returns `RunWalk(cols, wholeRing)`: the run holding column `t` of segment `a -> b`,
  walked both ways until a column fails `ok` or the window ends; reads only the cells on the run plus one cell at each end.
  `wholeRing` is true only when the walk comes all the way round with every column passing (start-dependent: the caller uses
  `chainThrough` + `QuayTrace.runsOf`).
- Detail the plan did not spell out: a ring run that wraps past the seed segment (the failing columns lie in the seed segment itself, or the
  backward walk reaches the far end of it) is handled by testing the rest of the seed segment from both sides; it is an ordinary run, not `wholeRing`.
- Tests (`QuaysTest`): `aRunWalkGivesTheChainsRun` (200 fields, first/middle/last column of every expected run, 41,907 walks, 22,086
  whole-ring answers, all checked), `anAllQuayRingIsReported`, `aRunWalkReadsOnlyItsCells` (<= 4 * cells + 16 nodes).
- Mutation checks: forward walk stops one column early -> `aRunWalkGivesTheChainsRun` and `anAllQuayRingIsReported` fail; `otherEnd`
  ignoring which segment holds the point (saddle bug) -> the suite fails.
- No behaviour change in the planner (nothing calls the walker yet; step 3 does). No timings taken.
