# SKIPROLL: skip terrain reads for region cells that can never settle

Branch `claude/p6-skiproll`; option D of [regionperf-decision](../review/regionperf-decision.md), approved by John 2026-10-31.

## What changed
- `RegionPlanner.decide` returns an unsettled decision right after the roll is drawn when `roll >= baseChance * BiomeClass.maxMultiplier()`. The bound is derived: `maxMultiplier()` is the largest value in `region/biome-classes.json` (and its default), 1.0 today, so the bound is 0.65 (times `config.frequency()`, which scales `baseChance`). A footprint's suitability is an average of multipliers, so it cannot exceed the maximum, and the coastal factor only lowers the chance.
- Region map choice: **new reason "roll" with empty numbers** (suitability, chance, water, peak, groups 0 or empty, centre = the site, no distance to water). Not a flag per path: one code path, simplest. `RegionPlanner.skipDeadRolls` (default true) exists so tests can compare with the full reads.
- The map used to show water/peak/unsuitable for those cells (about a third of all); it now shows roll (dark grey). Goldens `golden/region/{12345,987654321,join-*}.txt` regenerated: checked that every settled line and every claimedBy column is unchanged (only centre/radius/reason text of unsettled cells moved). Viewer dumps `viewer/fixtures/region/roads-*.json.gz` regenerated (`RoadsCommandTest` caught them). `RegionPlannerTest.waterWorldRejectsEveryCellForWater` now accepts "roll" for cells whose roll is over the bound.
- `mod/perf-budget.json`: `region.cold.warm.sparseColumns` budget 70000 to 52500, ci 85000 to 64000 (deterministic count).
