- `Districts.Build.quayWholes()` now asks the settlement's shared `QuayTrace` (`src.shared("quayTrace", exact, ...)`) for the runs near the tile: `near(bank, tile, QUAY_REACH + WIDTH/2)`, then the exact footprint filter (a column's footprint reaches 1 block below it and 2 above, so the trace's symmetric "column within m + 2" is a superset). `src.quayReference()` still selects the verbatim whole trace.

- `warmQuays` runs `QuayTrace.all` on the shared trace. New test accessors `Districts.allQuayRuns` and `allQuayOrder`; `WorldPlanner.newSource(site)` (package-private) gives a source that shares nothing (fresh trace, fresh junction field).
- `QuayTrace`: the stand-in `WholeWindow` is gone; the chain source is step 1's walker (`Quays.seeds`, `Quays.chainThrough` with the area's cell window), built per request over the caller's bank (a bank is one thread's `Build`); the node memo stays shared. `near()` prefetches its seed-scan box in one call.
- Verifier fixes: `clusterMembers` is published before any `clusterOf` entry (the NPE race); a grade that calls back into the trace for the cluster it is grading throws instead of deadlocking; `orderKey(canonical, r, part)` = `{smallest, first, size, tie rank, part}` on the oriented run, part index in `quayParts` append order.
- Ties: `canonicalQuays` breaks a (smallest, first, size) tie by the column sequence, in both paths. Tied runs share their smallest column, so they are always in one cluster, and the tie rank in a cluster equals the rank in the settlement. No fixture has a tie (asserted), so no output changes.
