# PARREADS: parallel terrain reads for cold settlement planning

2026-10-28, lead-coder, branch `claude/p6-parreads`.

## What was done

A cold metropolis is dominated by exact vanilla noise read on one thread (REGIONPERF, COLDCHUNK, the metropolis profile). The noise is a pure
function of seed and position, so the reads now run on several threads while the planner's own logic stays single-threaded and in its own
order. Nothing a planner answers changes.

- **Core API** (`planner-core`, no Minecraft): `core/cache/Fanout` (caller-runs fanout: the caller takes pieces from the same counter as its
  helpers, so it never waits for a piece nobody started: no deadlock from a pool thread, a vanilla worldgen thread or a nested fanout);
  `core/probe/ParallelReads` (`prefetch(boxes)` fills the exact probe's memo ahead of serial reads, `fanout()`), carried by `WorldProbes.reads`
  and `SkeletonSource.reads`; `BoundedCache.getOnce` (single-flight `get`: threads that miss one key together compute it once).
  `ParallelReads.NONE` (CLI, recorded probes, all other tests) is serial and prefetches nothing.
- **Where it is used**: the quay trace (`Districts.settlementQuays`) prefetches each row of waterfront tiles as its contour walk reaches the row
  before, then each contour chain before its runs (the whole waterfront is about 24,000 chunks, three memos' worth, so it streams); the junction
  field (`JunctionField.build`) prefetches the ends of every edge its grid-line tests read (`StreetRules.gridSideLand`, the terrain-free half of
  `gridSideEdgeOk`) and the centre columns of its whole streets; region resolution (`FieldRegionView`: claimant decisions in `claimantsNear`,
  `resolveAll`), the road graph (`RoadNet.scan` resolves its cells in parallel; `cellEdgesOf` computes each nearby settlement's links in
  parallel) and `WorldPlanner.warm` (the 25 cells' own resolutions, the member cells' skeletons, then the junction fields and the road links side
  by side, each cell's links in parallel).
- **Warmer**: `WorldPlanner.warm(x, z, r, true)` runs each settlement's quay trace right after its junction field, beside the road links;
  `RegionWarmer.warmAt` uses it, so a waterfront city's trace starts as early as it can, on our pool (the profile's 104 s freeze was the trace
  running inside a structure start the server thread waited on).
- **Mod**: `LiveReads` (prefetch into `ColumnMemo`, at most half the memo per call, nothing when the fanout is serial); `ColumnMemo` and
  `SparseColumns` fill through `getOnce` and count real fills (so the count rows stay exact under threads); `Workers` starts a reads pool
  (`fractalbuildings-reads-N`, a third of the CPUs, 1 to 6, `-Dfractalbuildings.readThreads`) with the server, and `WorldPlanners` builds every
  world's probes over it. `PerfPlannerTest` builds the same pool, so its rows measure the game's reads.

## Decisions and surprises

- Prefetch, not parallel logic: the planner code paths stay serial, so the byte-for-byte argument is "the memo holds the same pure values sooner".
  Region decisions and links are parallel per unit, but only through memoised pure functions the serial loop then reads.
- A prefetch is capped at half the memo; the quay trace streams by tile row and by chain, because the whole waterfront would evict its own start.
- The serial count of chunk fills in the quay trace is 30,413 (24,425 distinct chunks); the parallel run fills about 33,000: the tile-row boxes are a
  little wider than the contour reads.
- `Caches.all(2)` with `warm` on a town with roads takes over 10 min even serially (NOTES); the planner test uses default caches.
- In mod unit tests (no server) biome tags are unbound and `BiomeAliases` memoises nothing: about 2 s of caller CPU per metropolis phase of
  `PerfPlannerTest` (NOTES).
- The snow-city gate is the slowest warm (530 s serial, 344 s with the pool, both under load): a stack sample of the caller shows about half of it
  in `BiomeAliases` catching "Tags not bound" on coarse-lattice biome reads (the town wall ring's water tests), the unit-test harness artefact
  above, not noise. In the game the tags are bound and the alias is memoised.
- The metropolis profile's 104 s freeze (a structure start running the quay trace while the server thread waits) is shortened, not removed:
  the trace now runs on the reads pool too, and the warmer starts it earlier, but a chunk that asks first still runs it in its start.
