# 6.36 RUNGUARD: test runs can't pass while testing the wrong thing

Assistant, 2026-11-02, branch `claude/assist-runguard`. Item: [ROADMAP 6.36](../ROADMAP.md), from [polish-triage](../review/polish-triage.md) item 2.

# What was done

1. **Unknown `FB_ONLY` names.** `scripts/client-test.sh` now checks every comma-separated name in `FB_ONLY` against the client test classes before it takes the heavy lock, and exits 2 with the list of valid names. It finds them with the same scan `mod/build.gradle` uses to register them (`implements FabricClientGameTest` under `mod/src/gametest/java`). Naming `FlyThroughClientGameTest` without `FB_FLY`, or `PerfClientGameTest` without `FB_PERF`, also exits 2, since those opt-in tests would skip themselves. Inside the game, `ClientLayers.only()` makes the same name check against the registered `fabric-client-gametest` entrypoints and throws, so a bare `./gradlew :mod:runClientGameTest` fails instead of passing. `FB_ONLY` now takes a comma list (`scripts/test-scope.sh` already printed `FB_ONLY=A,B`, which used to match nothing).
2. **Environment through `scripts/remote.sh`.** ssh carries no environment, so the job's runner now exports the knobs itself: every exported `FB_*` variable, plus `JAVA_TOOL_OPTIONS`, `PERF_SKIP_FAR`, `PERF_LOAD_SKIP` and `FRACTAL_TEST_MODS`. It is a pattern whitelist with a deny list, so a new `FB_*` knob is forwarded without anyone updating a list. Withheld, each with a "not forwarded" line: `FB_VK*` (the worker renders on its GPU; `--cpu` for lavapipe), this host's lock and tooling knobs (`FB_HEAVY_LOCK`, `FB_SUITE_*`, `FB_QUIET_*`, `FB_POSTMERGE_*`, `FB_SNAPSHOT_*`, `FB_SB_*`), and absolute paths outside the worktree. A path inside the worktree is rewritten to the same path in the worker's copy. `FB_REMOTE*`, `FB_ANY_*`, `FB_WORKERS_CONF` and `FB_SUITE_SLOT_HELD` are withheld without a message. The forwarded list is printed, written into the job log ("environment from the waiter") and kept in the state file (`env=`, shown by `--list`). `env X=Y CMD` still works and overrides a forwarded value. `scripts/anywhere.sh` hands its environment to remote.sh, so it gets the same forwarding.

Docs: CLAUDE.md (the `FB_ONLY` line and the remote.sh line), `.claude/agents/coder.md`, the headers of remote.sh and anywhere.sh, and two NOTES lines (the feature, and a load flake in anywhere-selftest).
