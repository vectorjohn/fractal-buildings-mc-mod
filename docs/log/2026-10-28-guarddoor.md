# GUARDDOOR: curtain guard door clear of the stair cuts

Latent bug from the GALLERYROOMS verifier. A curtain whose neighbouring tower doorway is lower than its walk gets a stair cut at that end (`WalkOps.ramp`, k < 0: ramp columns 0..-k-1 and a closing wall at -k, mirrored east). `Brief.MAX_STEP` is 10, so the cut plus wall reaches column 10 (or w-11 at the east end). The guard door was drawn from `a+10 ..`, so it could sit exactly on the closing wall: a door into solid blocks.

- Test first: `RoomWalkTest.aCurtainGuardDoorIsNeverInsideAStairCut` (widths 24/28/36/48, walks -10/-10, -10/0, 0/-10, -10/+10, 60 seeds each): asserts furnished-rooms-walkable stays clean and the door lies strictly outside both cuts. It failed before the fix (assertion on the door position), passes after.
- Fix: `CurtainType.facade` draws the door from `MAX_STEP + 2` columns in at each end (12) instead of 10. Chosen over limiting the cut because the cut length is set by the height difference (a shorter cut would leave a drop of more than one block to the neighbour's doorway), and the shell is generated without the brief, so the door cannot react to the actual step. The door only moves a little towards the middle; DS-48 (lit bare gallery, chest hooks) is unaffected, the cut still drops its hooks via `walkClear`. Min curtain width 24 leaves a draw range of 0, i.e. fixed pos 12 (west wall at most 10, east wall at least 13).
- Verification: `check --seeds 0..99 --types wall,curtain,bastion --lots 24x12,36x14,48x14 --fronts south,north`: 158400 cases, 0 failing, before and after (note that it uses no walk brief, so it does not exercise the cut; the new unit test does).
- Goldens: only `golden/v1/curtain.txt` changed (the door position draw); the other types' digests are unchanged. Regenerated by copying `build/golden/v1/curtain.txt`.
- Fast suite (`test-all.sh --no-client`): the only failure was `GoldenDigestV1Test` (curtain), fixed by the regeneration; `GoldenDigestV1Test` and `RoomWalkTest` pass after it.
