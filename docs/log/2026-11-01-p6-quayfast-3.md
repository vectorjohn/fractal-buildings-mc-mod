# QUAYFAST step 3: the quay trace works run by run

Branch `claude/p6-quayfast-3` (lead-coder). Plan: [quayfast.md](../plans/quayfast.md) step 3. Step 1's walker (`claude/p6-quayfast-1`, 0aad5deb) is merged into this branch.

## Done

- `QuayTrace.near` no longer walks whole contour chains. It goes through every contour column of the tile's scan cells that lies within the reach of the tile. For each quay column (`ok`), it finds the run through it with `Quays.runThrough`, which walks both ways until `ok` fails. If a ring is quay all the way round, its run is taken from `chainThrough` plus `runsOf`, the same path as the whole trace.
- Clusters are now clusters of runs: kept runs (40 columns or more) with columns within `MEET_REACH` = 4 blocks of each other. `partnersOf(run)` scans the segments of cells within `CLUSTER_REACH` of the run's columns. The column-distance test is the meeting test.
- New state: a trace-wide `ok` memo, `runs` (id = smallest column key), `runOfCol` (with a `NO_RUN` marker for quay columns on no run of 2 or more), and run-keyed partners and clusters. Chains are kept only for `all()`.
- `all()` still contours the whole window. It registers every chain's runs (`allRunsOf`, which is `runsOf` without the length filter) into the same maps, so `all()` and `near()` share one representation.
- Walks run serially on the caller now: a run is tens of columns. Cluster grading still fans out through `gradeAll` (`Bank.fork`).
- `ChainSource`/`withSource` are removed (no test used them). The test hook `maxClusterChains` is renamed `maxClusterRuns`, and `splitsAChain` is new.
