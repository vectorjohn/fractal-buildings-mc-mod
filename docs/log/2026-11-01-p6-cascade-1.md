## Finding

In this single-thread order the **first `plan` already pays the whole cascade** (link rule 10,977 fills, exit cut 2,020): the district planner asks `exitServedAt` through `withExitServed`, not only the neighbours' trim. The 8 neighbours then add 353 fills. In the server run the same work lands on a neighbour's worker because the chunk thread reaches it through `ground`. So the row is the total of plan plus neighbours (an A1/A2 change must cut the total), and the neighbours-alone column is small by construction. The link rule is 60 % of the fills, the junction field of the settlements it plans 26 %.
